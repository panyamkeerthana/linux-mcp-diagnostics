# Scenario 4 — Cascading DB Failure (Disk + Permissions)

Two blockers are stacked — fixing the first alone still leaves MariaDB down.

The MCP server needs to:

1. Identify the first failure as "No space left on device" (Errcode 28), with the filesystem
   holding `/var/lib/mysql` at 100%.
2. Locate `/var/lib/mysql/DISK_HOG` as the file consuming the space and remove it.

```bash
df -h /var/lib/mysql
du -ah /var/lib/mysql | sort -rh | head
rm /var/lib/mysql/DISK_HOG
```

3. Retry the start, see it still fail, and identify the second failure: "Permission denied"
   (errno 13) on `/var/log/mariadb/mariadb.log`.
4. Find `/var/log/mariadb` owned by `root:root` instead of `mysql:mysql` and correct it.

```bash
chown -R mysql:mysql /var/log/mariadb
systemctl restart mariadb
```

5. Verify `mariadb` is active (running), disk usage is back to normal, and the database accepts
   connections.
