# Scenario 2 — SSH Permission Lockdown

The MCP server needs to:

1. Identify that public key authentication for `testuser` is rejected because `sshd` refuses to
   read the key, not because it is missing.
2. Check the SSH logs (`journalctl -u sshd` or `/var/log/secure`) for "bad ownership or modes for
   directory /home/testuser/.ssh".
3. Find `/home/testuser/.ssh` set to `0777` and restore the permissions `sshd` requires.

```bash
chown -R testuser:testuser /home/testuser/.ssh
chmod 700 /home/testuser/.ssh
chmod 600 /home/testuser/.ssh/authorized_keys
```

4. Verify with a key-based SSH login as `testuser`.
