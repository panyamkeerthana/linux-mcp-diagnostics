# Scenario 3 — OOM Kill via Systemd

The MCP server needs to:

1. Identify that `chronyd` is killed by the OOM killer, not that the host is out of memory.
2. Check `systemctl status chronyd` / `journalctl -u chronyd` for the OOM evidence
   (`status=9/KILL`, `Failed with result 'oom-kill'`).
3. Trace it to a systemd memory limit of `MemoryMax=1048576` (1 MB) set by the drop-in
   `/etc/systemd/system.control/chronyd.service.d/50-MemoryMax.conf`.
4. Remove the limit, reload systemd, and restart the service.

```bash
systemctl revert chronyd
systemctl daemon-reload
systemctl restart chronyd
```

5. Verify `chronyd` is active (running) and `MemoryMax` is back to `infinity`.
